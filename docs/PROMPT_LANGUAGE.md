# 提示词引用语言 v1

设计日期：2026-10-03。关联架构基线：revision 34；revision34 仅整理可维护性，保留 revision33 语言行为与 revision24 通用资源选择的编译契约。

## 状态与交付边界

本轮交付语言规范及独立编译核心 `PromptReferenceLanguage`。它把引用编译成明确的选择计划，并提供字段位置和中文诊断；它不读取资源、不生成提示词、不执行模型或动作。

**revision47，2026-10-09，基于 `1c7036d1`：History、静态资源查询与调用结果 slug 引用已接入原编译器。** 静态查询仍按 execution5+ 的原能力范围解释；execution9 新增动态 `main/group` 的来源／调用／节点 slug、标签、版本和 XML 读取。目录 `folder/under` 与静态资源历史版本尚未绑定，使用时明确报告；下文仍含未来编译契约，不表示全部已可运行。当前 LibraryFormat17 可读1–17，新执行9，旧执行1–8保留原解释。编辑器输入 `//` 打开补全，插入的格式仍为两层花括号；旧式 `{{result.key}}` 地址继续兼容。

已接入的 History 用法：

```text
{{type:builtin.in:history.name:messages.from:start-1.through:start-3}}
{{type:builtin.in:history.name:messages.from:end-3.through:end-1}}
{{type:builtin.in:history.name:messages.from:start-10.through:start-20}}
{{type:builtin.in:history.name:context.from:percent-25.through:percent-75}}
{{type:builtin.in:history.name:context.view:recalled.revision:2}}
{{type:builtin.in:history.name:messages.source:model.from:end-3.through:end-1}}
{{type:builtin.in:history.name:context.source:display}}
```

`messages` 读取未经摘要替换的 BODY 楼层；`context` 使用历史包装与同来源的有效摘要。`source:display`（默认）使用最终显示正文的语义文本，`source:model` 使用助手初始模型原文；用户楼层仍使用对应用户文本。旧楼层没有原始模型档案时报告缺失，不以显示正文伪造。每条用户或助手 BODY 消息算一楼，取范围发生在摘要替换和 API 角色合并之前。端点为 `start-N`、`end-N`（正整数）或 `percent-N`（0–100 整数），两端均包含；选择数量不足时只返回实际存在的楼层。字段顺序仍然无关。指定 `view` 后读取副本自己的来源捕获和压缩选择；`revision` 为副本的正整数版本，省略时读可用最新版。

整块只放这一条 History 引用时按结构化消息插入，保留角色和楼层边界；嵌入普通文字时展开为文本。原有 `{{history}}`、`{{history.text}}` 使用主调用的已处理显示历史，`{{history.raw}}` 仍是未经摘要包装的显示文本，不改旧语义。新增 `{{history.display}}`、`{{history.model}}` 为两种来源的明确原楼层投影；`history.display.summary`、`history.model.summary` 是对应来源的有效记忆 ID 目录。History 副本只保存消息修订引用、来源种类与压缩／展开差异，不能把它当作普通文本宏的更新链；副本的 `revision` 和文本宏的 `at:version-N` 是不同概念。

设置中创建标签，词条保存稳定标签 ID；改标签名称或 slug 不批量重写分配。角色、提示词包、主调用、调用组、调用、节点输出、词条、提示词块和用户身份均有 slug。新的显示名称不能为空，可用中文；英文 slug 与编译器共用 `[a-z][a-z0-9_-]*`，同级查重。现有命名空间、词条键和结果键保持原样，界面仅展示引用地址。基本角色字段保留原键，允许编辑新的显示名称与 slug。

## 单个 History 引用的局部格式（revision 33）

History 的楼层、原发言方和模型接口角色是独立概念。`format` 只用于 `builtin/history/messages` 或 `context`，值为双引号包裹的格式 JSON；可视编辑器负责两层引号转义，不需要手写。格式包含 `floorPrefix`、`floorSuffix`、可空 `apiRole` 和按原发言方匹配的 `speakers`。`speakers` 规则复用 `speaker/apiRole/prefix/suffix`；同一原发言方不能重复。未知键、无效角色和错误包装占位符报告错误。

没有 format 的引用继续使用已有默认规则。显式 format 的默认前后缀为空、保留原角色；通用设置只属于该引用，原发言方规则覆盖通用设置，规则的 null 字段表示继承，空文本表示明确不加包装。例如原始 ASSISTANT 的前缀写 Gary，并把 API role 设为 USER，不会改变原始 USER 楼层的名字、文本或角色。`{{speaker.name}}` 读取消息存档姓名，`{{speaker}}` 读取原发言方，`{{floor}}` 读取原楼号；老记录缺少姓名时沿用现有身份回退。

统一发送角色不会合并楼层。整块只写 History 时，格式作用于各条发送消息；混在普通文字中时只展开文本，整条消息的 API role 由外层配置决定。摘要保留自己的记忆标签，不伪造单个人名。包装与角色映射发生在来源/修订匹配之后，不修改 History、摘要标记、全局设置或捕获，不产生保存的副本。

新执行8的宏扫描识别引号，JSON 内的花括号和局部 speaker 占位符属于数据；旧执行1–7保留旧词法。显式填写完整的 from/through 会读取完整范围，不再误当主调用范围继承；未填写仍保留既有范围规则。用户在实际失败调用的提示词编辑器修改此参数时，仍使用冻结环境续跑，不绕过恢复契约。

## 设计原则

用户能从引用本身看出来源、范围、名称、筛选与版本。常用引用由可视菜单生成，手写与菜单共用解析结果；英文引用旁边显示中文名称和路径。

包容性来自明确的组合与扩展边界：同一来源可以增加词条、标签、调用和输出，不必修改主调用的逐条引用。未知规则须提示，不猜含义、不忽略条件。

分为三种职责：

| 层 | 负责 | 现有基础与本轮边界 |
| --- | --- | --- |
| 引用与选择 | 从指定来源选单个目标或一组目标 | 独立编译器；History 与静态角色／包已绑定 |
| 条件逻辑 | 比较、与／或／非、存在性及显式数值转换 | 保留 `ConditionExpressions`，后续接入同一目标读取器 |
| 文本变换 | 正则、替换、数值处理及格式整理 | 保留 `TextProcessing` 的有序纯处理，发生在使用内容的位置 |

角色、插入深度、调用触发、模型和输出布局仍属于各自配置。选择表达式不偷偷改变这些设置，也不执行写入、网络、脚本、循环或模型调用。

## 基本形式

```text
{{type:pack.in:world.name:muyao}}
```

字段使用 `字段:值`，字段间用点分隔。字段顺序无关，下面两条是同一个选择计划：

```text
{{type:pack.in:world.name:muyao}}
{{name:muyao.in:world.type:pack}}
```

可在字段和分隔符周围加空白。普通值中不能夹空白。编译器接受完整双花括号或裸表达式；完整模板的扫描仍由后续集成层负责，不能拿整篇提示词当成一条引用编译。

新英文标识和标签采用 `[a-z][a-z0-9_-]*`。大小写不自动转换，中文用于显示名称；名称改动不应隐式改变英文标识。旧中文或含点的标识继续使用旧引用，接入迁移时再明确处理，不自动音译或猜测替换。

目录的英文路径以 `/` 连接各级标识。英文地址、中文路径都由同一目录结构派生，不能独立维护两棵树。

## 字段契约

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `type` | 来源类型 | 必填；v1 为 `pack`、`character`、`main`、`group`、`builtin` |
| `in` | 来源的英文标识 | 必填；`*` 表示该类型中已加载、可见的来源，不是全库 |
| `call` | 来源内部的调用英文标识 | 仅 `main/group`；其单取必须指定；在所属资源内唯一 |
| `folder` | 某目录这一层 | 仅 `pack/character`；不包括子目录 |
| `under` | 某目录及全部后代 | 仅 `pack/character`；与 `folder` 互斥 |
| `name` | 目标词条或输出宏的英文标识 | 有它就是单取；不能搭配 `in:*` |
| `tag` | 必须拥有的一个标签 | 可重复；同一目标须满足全部 `tag`；重复相同标签去重 |
| `any` | 至少拥有其中一个标签 | 一次非空逗号列表；仅出现一次 |
| `not` | 不得拥有这些标签 | 可重复非空逗号列表，合并排除；任意一个命中即排除 |
| `at` | 内容版本 | 仅单取；默认 `latest`；详见版本规则 |
| `xml` | 单条文本内的元素路径 | 仅单取；`builtin` 不允许；不是 XPath |
| `from` / `through` | History 范围的起点／包含的终点 | 仅 `type:builtin.in:history.name:messages/context`；端点规则见上文 |
| `source` | History 文本来源 | 仅 History；`display`（默认）或 `model`，与摘要／副本来源一致 |
| `view` | 已保存 History 副本的英文标识 | 仅上述 History 来源；不复制原文 |
| `revision` | History 副本的固定版本 | 须与 `view` 同用；正整数，省略为当前可用最新版 |

其余字段只能出现一次，重复相同值也报错；不采用最后一项覆盖前一项。未知字段、未知来源类型、空值、尾随逗号、`tag:a,b` 都提示错误。标签各组之间是 AND。

没有目录字段时，范围为来源内全部词条；明确 `folder/under` 后再按 `name/tag/any/not` 选择。`name` 不意味着挑第一条：绑定后出现多个同名目标须报定位歧义。目录内词条名唯一，跨目录可以重复，因此在存在同名时必须加明确目录范围。

来源 slug 在同类型内唯一；目录和词条的英文标识在同一父目录共用唯一空间。显示名称也按用户要求同级去重。标签允许重复，不构成地址。

## 批量引用与同级替换

```text
【登场角色的性格与身份】
{{type:pack.in:world.under:cast.tag:identity.tag:personality.not:spoiler}}
```

以上选择 `world` 包的 `cast` 目录和后代中，同时具有 `identity/personality`、没有 `spoiler` 的词条。之后增加符合规则的词条，主调用不用逐条添加宏。

如果身份和性格分别存在不同词条，使用 OR：

```text
{{type:pack.in:world.under:cast.any:identity,personality.not:spoiler}}
```

标签选择整条资料，不从正文里猜出“性格那一段”。选部分内容须拆词条或用单条 XML 路径及消费者处的文本处理。

跨包批量选择必须明确写 `in:*`：

```text
{{type:pack.in:*.tag:cast.not:spoiler}}
```

执行契约：选来源与范围 → 标签选候选 → 现有启停与激活规则 → 读取有效内容 → 按编辑器目录／词条顺序输出。跨来源使用捕获环境的加载顺序；相同目标按稳定身份去重。最后稳定身份只作同序号的确定性兜底，不按英文名偷偷重排。

表达式字段顺序无关；最终资料输出顺序仍然确定。标签是组织属性，启用与触发条件是运行状态；不能为了表示本轮登场而要求用户每轮重写标签。

## 调用产生的宏

```text
{{type:main.in:daily.call:status.name:current}}
{{type:group.in:affection.call:update.name:score}}
```

当前绑定：`in` 是主调用／调用组的 slug，`call` 是 `Workflow.slug`，`name` 是 `WorkflowNode.slug`，读取该节点主输出。保留稳定身份与实际写入来源校验，不靠显示标题或节点序号推断归属。正则副本与其他显式写入目标仍可通过原有输出键地址读取；不会为现有数据自动重命名输出键。不同调用可有同名节点，单取不唯一时须进一步指定来源与调用。

调用配置声明输出宏的名称、标签和稳定身份。生成时更新内容、启停状态和版本，不每次创建一个新的宏身份。调用能产生多项输出，实际目标与写入者分开；宏处理动作可以更新另一来源的目标，不因这次写入就夺走目标归属。

声明可出现在补全里，但不保证当前已有数据。绑定后须区分：不存在、来源未加载、已关闭、激活条件未满足、本轮结果尚不可用、内容为空、内容可用。当前生产者被屏蔽时不得回退到旧结果；历史读取需要显式版本。

## 版本与 XML

```text
{{type:group.in:affection.call:update.name:score.at:update-1}}
{{type:pack.in:world.name:muyao.xml:profile/personality}}
{{type:pack.in:world.name:muyao.xml:"profile/ns:detail.name"}}
```

- `latest`：捕获环境中的当前有效值，沿用当前结果屏蔽规则。
- `turn-N`：沿用当前 `MacroReferences.currentTurn`，按 USER/BODY 消息计数的用户轮次回退 N 次，再取那个截止点最近的可见值；不是任意 user/assistant 消息的楼层索引。历史宏自身的楼层选择继续独立。
- `update-N`：沿目标更新链回退 N 次；0 是最近一次。
- `version-N`：目标链的绝对版本号；从 1 开始。

数字须在非负 Int 范围内，绝对版本号须大于 0。`builtin` 只接受 `latest`，因为内置投影不等于普通动态宏版本链。

单条版本先定位捕获环境中的目标，再取其内容版本；不表示把目录和标签也回滚到过去。没有 `name` 的集合禁止 `at/xml`，包括显式 `at:latest`，避免把“每条的旧值”与“历史时刻的成员集合”混为一谈。后续若需要集合历史，要单独定义集合快照。

XML 路径逐级选现有元素，沿用当前元素名称规则，不支持谓词、任意 XPath 或实体声明。含点、冒号的元素名用双引号保护分段：只有 `xml` 字段允许引号，只接受 `\"` 与 `\\` 转义；未知转义提示错误，不开放换行字符串。解析 XML 在后续读取阶段完成，编译阶段仅检查路径语法。结构化消息不能通过 XML 字段被强制变成文本。

新选择语法不混用旧的 `@/#`；其版本和 XML 使用 `at/xml`。旧引用的两个后缀保持原义。

## 与条件、处理及聊天历史的衔接

后续条件 DSL 通过同一解析器读取目标，仍显式做存在性和数值转换。例如以下是**待接入**的组合：

```text
exists(macro("type:group.in:affection.call:update.name:score")) &&
number(macro("type:group.in:affection.call:update.name:score")) >= 20
```

正则保留在使用内容的触发、输入、输出、磁贴或宏处理处。实际纯处理有顺序，不能沿用选择字段的“顺序无关”规则。

接入层至少区分文本、数值、布尔、缺失、目标集合和消息集合。选择计划的单取／多取由语法决定，不能随一次命中数量变来变去。普通模板边界才将文本集合按规定分隔连接；条件使用明确的存在／数量／单取操作，不能对多取结果隐式选第一条。

聊天历史保留 `HistoryContext` 的结构化消息投影、角色、每层前后缀和楼层选择。建议内置来源范围为 `turn/user/history`，具体 builtin 名称在接入时列出固定词汇；此轮编译器不确认某个 builtin 目标实际存在。聊天历史返回消息集合，插入模型请求继续使用原有结构化边界；展开成文字须明确选择文本投影。

## 编辑体验与失败归因

光标进入宏：展示中文路径、来源、英文表达式和当前状态。单条可看内容；多取显示候选／有效数量和有序名单，可以展开查看为何某条被排除。这里是读取结果，不能因为打开浮层就运行模型或写入会话。

编辑菜单从来源、目录、名称／标签、版本生成表达式。菜单与手写使用同一个编译器和读取器，不能各自实现一套过滤。字段区间为原输入的 UTF-16 半开区间，与 Compose 光标一致，能定位错误字段及给出替换建议。

语法、未知来源或歧义属于配置问题，定位到相应提示词块；自动重试模型不解决这些问题。生成内容不符合已声明格式才走既有输出格式失败路径。直接当前单条的格式处理可以保持明确归因；集合、历史或混合多来源内容不能猜一个调用承担失败。

断点修复继续编辑失败调用的实际提示词。用新保存的提示词重新编译，对照原冻结资源、原输入、历史、状态及已接受结果；不使用当前聊天的新环境，不重复已成功的动作。语言诊断应保留字段和调用位置。

## 核心结构与扩展边界

`PromptReferenceLanguage.compile(source)` 输出：旧引用、具体 `QueryPlan`，或带位置与错误码的诊断。错误时不返回半可执行计划。字段位置独立于计划语义，不能让调换字段顺序导致语义键改变。

编译器使用线性扫描与不可变计划，不依赖 `Library/Session`、Android、数据库或模型。入口限制一条引用最多 4096 个 UTF-16 单位；不为未知风险叠加目录深度、词条数量或层层防御框架。

v1 用具体枚举、数据类和小型字段规格实现；不创建运行时脚本插件或通用注册框架。词法扫描不认识业务资源结构，来源绑定与有效内容读取独立。新增来源在一个绑定边界接入；新增字段要明确重复、值形状、允许来源及类型，补充一致的诊断和菜单定义，不在多个前缀判断中散落分支。

v1 的标签形式表达“全部必有＋一组任选＋全部排除”，尚不表达任意嵌套标签布尔式。若实际需求需要多个 OR 组或更复杂筛选，应增加明确的高级谓词字段并编译成布尔语法树，保持常用字段不变；不能用重复 `any` 偷偷改变 AND/OR 含义。具体新增谓词、集合快照和运行时插件注册均属后续需求，不预设实现。

未来缓存分三类：表达式编译计划；来源／目录／标签元数据索引；一次捕获环境中的有效读取值。元数据变更更新索引，加载变更更新可见范围，状态／已接受结果／版本变化重新计算内容。缓存不能跨断点环境混用。本轮未实现缓存，也未测量性能；独立编译器已允许调用方保留并复用计划，不在每个字符变化时读取整个资源库。

## 稳定身份与接入次序

目前 `result.key` 仍是全局结果及版本地址。实现不同来源的同名输出，需要同步修改 `ResultReferences`、规划与屏蔽、`OutcomePublisher`、`RuntimeSnapshot`、`RecoveryPublication`、`TurnCheckpoint.macroLengths`、分支回溯及编辑器，不能只做新查询外壳。

目标身份采用明确的 entry／output／legacy 目标，使用资源与目标的稳定 ID；显示名称、英文地址和内容版本不充当内部身份。`MacroVersion.origin` 是写入者，`valueOrigin` 是内容来源，两者都不当然等于目标归属。

旧地址链只能一对一绑定到明确目标。无法确认归属时保留 legacy 兼容目标，不按每次写入者拆链，不合并不同链。保留绝对版本号、checkpoint 长度和已接受收据。改名／移动目录需按解析节点更新当前文档；既有存档和冻结断点不得跟着当前目录重写。

| 顺序 | 交付 | 完成条件 |
| --- | --- | --- |
| 本轮 | 规范＋独立编译核心 | 排列等价、标签组合、旧语法分流、位置及错误诊断可集中检查；预览语法不变 |
| 后续第一片 | 词条名称／目录／标签＋静态查询＋菜单／浮层 | 单取与批量查询从编辑到实际提示词结果贯通，保持现有数据 |
| 后续第二片 | 稳定目标身份＋动态输出＋历史／断点兼容 | 不同来源同名输出独立，历史不串链，成功收据不重放 |
| 后续第三片 | 类型化条件桥接＋消费者处理 | 集合和结构化历史不被隐式转成字符串，格式失败归因明确 |

每片都以真实受影响契约做最少必要检查，不新增示例聊天或调用真实 API。未贯通到运行时的编译能力不能称作“新宏已经可用”。
