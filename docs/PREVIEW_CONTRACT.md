## API (JSON)
- GET /api/health => {ok:true}
- GET /api/state => {library:<Library>,revision:<Long>,running:<Boolean>,runId:<String?>,streaming:<String>,traces:<array>,error:<String?>}. Library schema as core Models.kt.
- State GET returns an instance-scoped ETag. Conditional `If-None-Match` returns 304/no body when no library/run/presentation update occurred; the browser does not repaint/re-serialize the library on unchanged polls. Quiet background-tab polls pause. Manual Refresh requests the complete state. No additional state interpreter.
- Optional character avatar is `{mediaType:"image/jpeg"|"image/png",base64:string}` or null, at most 32768 decoded bytes. Both adapters prepare a 256px square JPEG locally from selected files (max source 10 MiB); metadata persists/exports with the card but never participates in macros or model inputs. Display falls back to first initial without an image; old imports require no migration. Shared core limits format/signature/bytes; platform decoder handles full image readability.
- GET /api/actions => [{id,title,description,fields:[{key,title,type,required,defaultValue}],usesModel:boolean}]. Action field type STRING/NUMBER/BOOLEAN/TEMPLATE; future options optional. Core descriptors serialize these fields. Web generic action arguments editor consumes fields.
- GET /api/character-fields => [{key,title,hint,legacyKeys:[string]}], seven permanent character fields from shared core. Editors display direct text areas in returned order, with immutable keys and no delete/condition controls for basic fields; extras use the existing entry form. Loaded library already includes normalized basic fields. Legacy keys identity/examples only for compatibility; instructions stays extra. New character defaults come from these descriptors. New chat preserves selected resource configuration and resets messages/state/results.
- PUT /api/library body {library,expectedRevision} => state JSON; reject 409 revision mismatch/running, 422 validation with {issues:[{path,message,error}]}. No credentials in library.
- POST /api/preview body {input,nodeId?:string} => {messages:[{id,role,text,createdAt}],issues:[{path,message,error}]}; append draft user to temporary session; label preview as compilation only, not execution of prior model stages.
- POST /api/run body {input,mode:"test"|"live",key?:string} => {runId}; append user once, run async with fixed snapshot, poll /api/state. Test mode explicitly named test gateway, no network, deterministic output showing rendered system/user content. Live mode user opts in, API key memory for run only. Mode never silently switches from test to paid provider.
- POST /api/cancel => state, cancellation discards staged reply/state/results.
- POST /api/sessions/new body {expectedRevision} => state; shared core creates a fresh chat inheriting resource selections only. POST /api/sessions/select body {id,expectedRevision} => state selects an existing chat. Both reject running/stale versions; creation/selection is immediately persisted. Browser refuses these operations with an unsaved draft and provides a save-changes button on chat configuration.
- POST /api/characters/select body {id,expectedRevision} => state; reject running/stale/missing card. If card differs from current chat, create/persist a fresh chat using selected card and current resource configuration; previous chats untouched. Selecting current card returns existing state. Browser card picker displays names and avatar placeholders, uses this endpoint without a second selection interpreter.
- GET /api/scenarios => [{id,name,description,checks:[string]}].
- POST /api/scenarios/load body {id,expectedRevision} => state; explicit UI confirm replaces CURRENT preview test library; backing file retained before replacing (root implementation).
- POST /api/checks => [{name,passed,detail}], actual shared-core deterministic checks, no paid API.
- GET /api/export => Library download (JSON only, no keys).

Errors JSON {error:<safe human message>,issues?:array}; do not log request/response bodies/keys. Origin/local Host checks on mutation, max JSON request size, no CORS open policy. Revision CAS and single active run prevent stale commits. Atomic preview persistence under preview-data/library.json; corruption/unsupported schema fails startup, never auto-reset. Configuration I/O not an Android database replacement.
