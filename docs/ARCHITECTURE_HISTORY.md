## Contracts decided for this milestone
- Stable resource IDs; separate unique namespace for character/package macro addressing. Display name can change independently. Character defaults follow CharacterFields.definitions: profile, appearance, personality, background, dialogue_examples, world, preferences. `character.name` remains the display-name macro; identity/examples are legacy fallbacks, instructions is an ordinary extra entry.
- Syntax `{{character.key}}`, `{{pack.namespace.key}}`, `{{category.name}}`, `{{result.key}}`, `{{results.category}}`, `{{state.key}}`, `{{input}}`. Optional XML selector suffix `#tag/path` for entry content. Missing optional macros expand to empty with issues. Unknown malformed syntax is a validation issue, never silent sending. No recursive template execution in entry text.
- Load, activation and insertion are distinct. Category reads only loaded active entries in resource load order then entry order. Fixed text is not discarded unless a block explicitly selects hide-when-all-references-empty. Conditions compare string or numeric session state using explicit enum operators. No AI calls for activation.
- Each main call/group contains workflow definitions with an event trigger and DAG nodes. `dependsOn` uses exact run node results; only explicit result macros refer to persisted results. Registry action IDs: `model.generate`, `text.render`, `state.set`, `state.increment`, `event.emit`. Each node has one outputKey, optional visible output, condition, input template, blocks and arguments. Dependency failures stop that dependent path, never fill with older output. Check cycles/missing dependencies/writer conflict before external calls. Disabled/condition-false prerequisites cause dependents to skip.
- Workflows matching the same event may execute concurrently but merge output/state deterministically; competing state/output writes in a parallel wave are errors before execution when statically knowable and before commit otherwise. State/result changes stage in run memory and persist atomically only on successful completion. Visible node streaming can be shown temporarily; partial responses are not silently committed as successful replies. Model inputs use a fixed resource snapshot. Event chains are bounded and workflows run at most once per chain. Events `user.message`, `reply.completed`, and custom emitted events. Engine itself emits reply.completed after a visible output; user trigger may route through event.emit to another workflow.
- User input is already appended to session.messages before core.run; includeHistory nodes send that history once, without duplicating input. includeHistory=false sends only explicit system/user node templates. Prior node result is available to dependency consumers in current run after its successful completion.
- Resource edits cannot change an in-flight snapshot. One run per controller, cancellation aborts staging. Creating/switching a session cancels current run before selection. API keys separate from exportable resources and stored via Android Keystore encryption. Logs/errors cannot contain raw response/request bodies or credentials.
- Session owns state/results/history and selects one primary card and one main call. Independent session IDs isolate all runtime data. Explicit selected packages plus bound packages deduplicated by stable ID. Bound loading is one level, no transitive graph in milestone 1. Disabling group stops its workflows/content; existing session state stays saved but group's results are excluded unless it is loaded again.
- Indexed SQLite record storage, resource JSON payload per record; transactional commit; no whole-library write on stream tokens. Repository is the replacement boundary. Bundle import/export schema=1 excludes API keys; validation occurs before transaction, conflicts reject atomically. Do not erase corrupt/unsupported storage silently.
